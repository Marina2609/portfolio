React

What is React?

React is a tool for creating user interfaces. Its main task is to ensure that what can be seen on web pages is displayed on the screen. React greatly facilitates the creation of interfaces by splitting each page into small fragments. These fragments are called components.

What is the React component?

The React component is a piece of code that represents a part of a web page. Each component is a JavaScript function that returns a piece of code representing a page fragment.

To form a page, we call these functions in a certain order, collect the results of the calls together and show them to the user.

React uses a programming language called JSX, which is similar to HTML, but works inside JavaScript, which distinguishes it from HTML.

Assembling components

React components can be placed in other components.

Component classes

Before that, we wrote components in the form of functions. They are called functional components. However, components can be written differently, in the form of JavaScript classes. They are called component classes.

Features of the component being created

Class-based components can store information about the current situation. This information is called state, it is stored in a JS object.

Changing a React component based on its state

State is a tool that allows you to update the user interface based on events.

In the render function, the this keyword always refers to the component inside which it is located.

How does the component react to events?

The user can interact with the component by clicking on the music playback button. We want to respond to these events. This is done through a function that handles events. These functions are called event handlers.

How the component should work

When the state of the component changes, it will call the render function again.

Events as properties

Properties don't necessarily have to be some kind of data. They can also be functions.

Feature of setState

  • When calling setState, the state change is not instantaneous. React waits a bit to see if any more changes need to be made, and only then makes a state change. This means that it is impossible to know exactly what the state of the component will be after calling setState.

  • If you change the state based on the previous state, you should pass setState to a function, not an object. This function takes the old state as an argument and returns an object representing the new state.
